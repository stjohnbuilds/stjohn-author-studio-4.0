NON-NEGOTIABLE RELEASE RULE

- Edit source only in this Script and Sync 3.0 folder
- The only real release/handoff folder is:
    Script and Sync Releases
- dist, .next, out, and similar folders are temporary build output only
- Never tell anyone to use an app from dist
- Never make extra duplicate release folders
- When rebuilding, archive the previous release into:
    Script and Sync Releases/Old
  and add the date and time to the archived name
- Then place the fresh Mac app and Windows release files back into:
    Script and Sync Releases

WHY THIS CONFUSES PEOPLE

- electron-builder writes temporary packaged files into dist while building
- that staging output can look like a finished app, but it is not the official handoff copy
- the only app copies regular users should open are the ones in Script and Sync Releases

SOURCE VS PACKAGED APP

The files in this folder are the source.
The Windows .exe and Mac .app are packaged snapshots of that source.

That means:
  - changing source files does NOT change an old .exe or .app automatically
  - after any source change, you must rebuild
  - always open the newly rebuilt app, not some older copy from another folder

LOCALHOST TROUBLESHOOTING

If localhost:3000 loads but nothing feels clickable, check the dev server first.

Best first fix:
  1. kill the old next dev process
  2. restart npm run dev cleanly
  3. refresh the localhost page

We have seen localhost previews get into a bad state even when the UI looks fine.
